# MPQTikTool 完整逆向还原路线与验收规范

> 本文是项目实施基线。功能状态必须由代码、自动化测试和真实样本证据决定；路线图中的目标不代表已经实现。

## 产品目标

将 Warcraft III MPQ/W3X/W3M 地图恢复为可检查、可复用、可编辑的工程。对每个数据块分别记录原始位置、名称可信度、解密/解压结果、校验值、格式解析结果和导出状态。任何无法解释的数据都必须保留原始字节，禁止静默丢弃或用占位数据伪装成功。

## 总体架构

采用分层、可替换、可独立测试的实现，WPF 只负责呈现和调度，不直接承担格式解析：

1. **Container**：容器定位、MPQ Header、Hash/Block/HET/BET 表、偏移与边界检查。
2. **Block I/O**：原始块读取、扇区表、解密、解压、CRC 和流式输出。
3. **Recovery**：名称候选、哈希匹配、匿名块命名、置信度与证据。
4. **Formats**：按格式注册解析器，统一提供识别、解析、引用提取和诊断。
5. **Map Model**：地图、地形、单位、物编、触发器、资源引用的统一中间模型。
6. **Reconstruction**：目录工程、MPQ 重建、重新打包、逐项哈希对比。
7. **Analysis**：JASS/Lua、字节码/私有容器识别、保护与变形特征报告。
8. **Application/UI**：工作区、任务队列、日志、进度、取消、问题列表、资源关系浏览。

核心数据对象建议统一包含：
- ArchiveDescriptor：容器版本、头偏移、表类型、偏移宽度、总长度。
- BlockRecord：块索引、原始偏移、压缩/解压长度、flags、locale/platform、哈希、名称候选。
- RecoveryEvidence：来源、候选名称、匹配算法、置信度、冲突和人工确认状态。
- ExtractionResult：读取/解密/解压/CRC 状态、原始与输出长度、SHA-256、失败原因。
- ParsedAsset：格式、版本、结构摘要、依赖、引用、解析警告。
- ReconstructionManifest：源块到工程文件的映射、变换记录、逐项校验结果。

## 第一阶段：MPQ 底层完整性

### 范围
- MPQ v1/v2/v3/v4；传统 Hash/Block Table 与 v4 HET/BET。
- 32/64 位偏移、扩展头、用户数据头、前缀偏移、大文件和边界检查。
- 压缩算法及组合掩码：zlib、PKWARE implode、BZip2、Huffman、ADPCM、Sparse 等；按 MPQ 规范处理掩码组合及顺序，不可把“某算法可解”误当作组合支持。
- 单块与扇区文件、加密扇区、扇区偏移表、CRC 表、FIX_KEY、文件名密钥和连续状态解密。
- 匿名 Block 按 Block Index 原样读取、解密/解压（可行时）和导出；无法解密时保留密文并标记。
- Patch/特殊块必须明确识别，不支持时拒绝误解析。

### 验收
- 每个版本都有最小化 golden fixture；合法、截断、越界、畸形表均有测试。
- hash/encrypt/decrypt、扇区边界、压缩算法与组合掩码均有独立测试。
- 对可解密块，输出长度必须精确匹配预期；CRC 可用时必须验证。
- 64 位偏移不允许先截断到 32 位；文件偏移、长度和加法全部做溢出/边界检查。
- 每个 Block 必须有明确结果：成功、密文保留、格式不支持、损坏、越界或取消。
- 任何未知块都能导出原始容器字节，不以“无法解析”作为丢弃理由。

## 第二阶段：资源和地图结构还原

### 资源解析器
- 图像：BLP1/BLP2、TGA，以及地图中实际出现的 PNG/JPEG/BMP 等。
- 模型：MDX/MDL，含版本、Chunk、几何、材质、纹理、骨骼、动画和事件。
- 音频：WAV/MP3/OGG 等；保留编码原件，不因预览解码失败而影响导出。
- 文本/脚本：JASS、Lua、INI、SLK、FDF 等。
- 地图数据：W3I、W3E、WPM、DOO、SHD、预览图、路径图等。
- 物编：W3U、W3T、W3A、W3B、W3D、W3Q 等，按版本和字段类型解析。
- 触发器/字符串：WTG、WCT、WTS；记录未知字段和原始片段。

### 统一地图模型
建立资源路径、纹理/模型依赖、物编对象 ID、单位/技能/物品引用、触发器函数/变量/字符串引用之间的关系图。引用解析必须保留来源文件、偏移/字段、目标解析状态；目标缺失时形成 dangling reference，不静默忽略。

### 验收
- 每种格式有版本检测、结构边界检查、解析摘要和未知字段保留。
- 对解析失败资源仍输出原始字节及可定位错误。
- 依赖图可从资源/对象跳转到引用方和被引用方。
- 结构化解析结果与原始数据长度、字段偏移可追溯。

## 第三阶段：完整工程重建

### 输出形态
- **RecoveredMap/**：恢复的地图文件目录，保留已确认的原始路径。
- **Assets/**：独立资源库，含原名、匿名别名和来源映射。
- **MapModel/**：地形、摆设、物编、触发器等结构化 JSON/可读导出。
- **Scripts/**：原始脚本、反编译/反汇编结果、分析注记分开存放。
- **Reports/**：完整性、不可逆项、缺失、保护、冲突、校验报告。
- **manifest.json**：每个源块到输出文件的可追溯映射。

### 重建规则
- 真实路径只允许来自 listfile、哈希候选验证、资源引用证据或人工确认；推断路径必须标注置信度。
- 匿名别名不能伪装成 MPQ 原始文件名，不能写入会误导工具的 listfile。
- 重建 Hash/Block Table 时必须维护哈希冲突、locale/platform、多语言项、空块和删除标记。
- 输出可编辑地图与独立资源工程；若某些对象/触发器已被物理清空，只能报告缺失，不能合成原数据。
- 重新打包后逐项比较解密/解压内容 SHA-256；另外比较结构化元数据、引用完整性和可打开性。

### 验收
- 输入块数 = 已处理块数 + 明确分类的失败/跳过块数。
- 每个输出文件都能追溯到源块，SHA-256 可复验。
- 重建包可被独立 MPQ 工具读取；可编辑地图须由目标 World Editor 实际打开验证。
- 报告区分：字节级可逆、结构级恢复、语义推断、人工确认、不可逆/缺失/受保护。

## 第四阶段：逆向分析能力

- JASS：词法/语法分析、符号和函数调用关系；可用时反编译，始终保留原始脚本。
- Lua：源码识别、字节码版本检测、反汇编；仅在 VM 版本和指令集匹配时尝试反编译。
- 自定义容器：魔数/长度/版本/熵/重复结构/嵌套容器检测，形成插件式探测器。
- 加密与混淆：区分已知算法、疑似变换、未知高熵数据；记录证据、假设和可复现步骤。
- 能恢复源码时将源码与原始字节并存；不能恢复时保留原始字节、反汇编、字符串、结构和分析报告。

### 验收
- 分析结论附证据和置信度，不把猜测标为确定。
- 反编译结果必须标注有损程度，不能覆盖原件。
- 平台私有算法或密钥缺失时，明确说明边界并保留完整原件。

## UI 工作台要求

UI 采用左侧工作区导航 + 中央数据视图 + 右侧检查器 + 底部任务/日志的桌面工作台布局。所有耗时任务支持进度、取消、阶段状态和错误详情。

### 页面
1. **总览**：输入地图信息、MPQ 版本、块数、文件数、表类型、容量、名称恢复率、解析率、校验率和风险提示。
2. **资源浏览**：名称/匿名块、类型、大小、Locale、Flags、偏移、解密状态、SHA-256；支持搜索、过滤、批量导出、十六进制和格式预览。
3. **MPQ 结构**：Header、Hash/Block/HET/BET 表、块布局、扇区表、压缩/加密/CRC 状态。
4. **地图结构**：地图信息、地形、摆设、路径图、物编、触发器、字符串；显示版本和解析警告。
5. **依赖关系**：资源/对象/脚本引用图，支持定位缺失引用。
6. **还原工程**：输出目录配置、路径冲突处理、打包、逐项校验和结果对比。
7. **逆向分析**：JASS/Lua、字节码、未知容器、加密/混淆证据。
8. **报告中心**：不可逆数据、缺失、保护、失败块、未识别格式、哈希校验差异和导出清单。

### UI 约束
- 不支持的能力显示“未实现/待验证”，不可伪装为可点击完成态。
- 所有表格支持复制、列排序、过滤和导出 CSV/JSON。
- 长任务不得阻塞 UI；支持取消、失败重试和日志定位。
- 预览失败与数据导出失败必须分开。
- 默认采用深色专业工具风格，信息密度高但层级清晰；危险操作二次确认。

## 工程实施顺序

1. 建立测试项目、固定格式 fixture 和统一诊断模型。
2. MPQ v1-v4 解析器与块读取重构；先覆盖正确性，再扩展算法。
3. 解压/解密插件化并逐项测试；补充 CRC 和 64 位流式 I/O。
4. 资源解析器注册体系和地图结构中间模型。
5. 依赖图、名称证据和完整性清单。
6. 工程重建、MPQ 重打包与逐项校验。
7. JASS/Lua/自定义容器分析。
8. UI 按工作台模块逐页接入真实服务。

## 当前已知基线（2026-11-11）

- 当前工程是 .NET 8 WPF，MPQ 读取为自研 C# 实现。
- 已有传统 MPQ 表解析、按 Block Index 枚举、部分名称恢复、有限资源嗅探/预览和导出。
- MPQ v4 HET/BET 尚未实现；压缩掩码覆盖不完整；还原器受传统表布局和 4GB 限制。
- 目前 MDX 是 Chunk 检查器，不是 3D 预览器；资源/地图结构解析、完整依赖图和可逆打包验证仍不完整。
- CI 成功仅证明构建通过，不代表真实地图端到端正确。
- README 中历史目标样本统计尚未形成可公开复验的 fixture 与测试，不能作为当前通用能力证明。

## 真实性原则

“完全可逆”只适用于输入中实际存在且可解密、可正确解释的数据。已物理删除的数据、缺少密钥的私有加密内容、未知且不可判定的变换，不可能凭空恢复。工具必须保存原始证据并明确标注边界。


## MPQ v4 实施进展（2026-11-12）

### 已落地并通过 CI 的能力

代码入口：`src/MPQTikTool/Services/MpqV4ArchiveParser.cs`。

- 解析完整 0xD0 v4 Header：ArchiveSize64、Hash/Block/HiBlock/HET/BET 偏移和存储长度、RawChunkSize、六组 MD5 字段。
- 对 Header 的 MD5_MpqHeader 执行 MD5 校验；对存在 MD5 字段的 HET/BET 原始存储数据执行校验。
- 对 HET/BET 扩展表执行表密钥解密；支持未压缩和 ZLIB 压缩表，其他压缩掩码明确报不支持。
- 解析 HET 的 NameHash1、BET 索引位数组；解析 BET 的 64 位 FilePos、FileSize、CompressedSize、FlagIndex、NameHash2。
- 使用 Jenkins lookup3 计算候选文件名哈希，将 HET/BET 名称哈希索引与外部 Listfile 匹配。
- `MpqArchive.Open` 已接入 HET/BET 读取路径，可按 BET Block 导出资源；v4 写回仍明确禁止。
- MPQ 结构页已绑定真实 v4 Header、HET/BET 表信息和 BET Block 条目；资源页显示解密/解压/CRC 状态。

### 自动化测试

自包含 SelfTest 当前 15 项，覆盖 Header MD5、HET/BET 原始 MD5、未压缩表、加密表、ZLIB 表、位字段、名称哈希、BET Block 读取和原始资源导出，以及 CRC 和传统 MPQ 基础路径。

最近一次完整 Windows CI：`43134361998`，Build、自测、Windows x64 发布、产物校验、ZIP 和预览发布全部成功。该结果对应当次提交，不等同于真实大型地图的端到端验收。
